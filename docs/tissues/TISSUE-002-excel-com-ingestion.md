# TISSUE-002：Excel COM 只读分块读取

- 状态：完成
- 类型：功能
- 优先级：P0
- 依赖：TISSUE-001
- 关联：[ADR-0001](../adr/0001-local-desktop-search-and-excel-automation.md)

## 目标

通过独立 Excel COM 实例安全地读取一个或多个工作簿，将有内容单元格及定位元数据按块输出给索引层，同时不修改源文件、不阻塞 UI。

## 范围

- 定义与 UI、SQLite 无关的 Excel 读取接口和数据传输对象。
- 在专用后台线程初始化 COM apartment，并使用独立 Excel 实例。
- 以只读、禁止链接更新、禁止宏执行的方式打开工作簿。
- 枚举工作表，获取工作表顺序、名称和有效数据边界。
- 按有限行块批量读取值及搜索所需元数据。
- 报告文件级、工作表级和块级进度。
- 支持协作式取消及单文件失败隔离。
- 在所有退出路径关闭工作簿、退出应用创建的 Excel 实例并释放 COM 引用。

## 有效范围规则

- 不扫描 Excel 的整张网格。
- `UsedRange` 仅作为候选范围，因为历史格式可能使其异常膨胀。
- 应使用 Excel 原生查找或等价方式确定最后一个含值或公式的行列。
- 仅因格式存在但没有值或公式的单元格不进入搜索索引。
- 隐藏工作表、隐藏行列的读取开关保留在接口中，默认值等待产品确认。

## 非范围

- 不负责值标准化和关键词匹配。
- 不写入 SQLite。
- 不实现导出。
- 不推断表头、表格边界或业务记录边界。

## 验收标准

1. 能读取 `.xlsx` 和 `.xlsm` 中所有工作表的非空单元格。
2. 输出包含文件标识、工作表名称及顺序、原始行号和列号。
3. 读取使用块级 COM 调用，没有按单元格循环调用 COM 属性。
4. 公式单元格能够输出 Excel 当前计算结果，并保留其为公式单元格的标记。
5. 源文件的大小、修改时间和内容在读取前后保持不变。
6. 用户取消后能在有限时间内停止，并清理应用创建的 Excel 实例。
7. 一个损坏或无法打开的文件不阻止其他文件继续处理。
8. 用户已经打开 Excel 时，不关闭或影响用户自己的 Excel 实例。

## 测试要求

- 普通、多工作表、空工作表、隐藏工作表和异常膨胀 UsedRange 样本。
- `.xlsx`、含宏但不执行宏的 `.xlsm` 样本。
- 文件占用、只读文件、损坏文件和取消路径。
- 重复运行后的 Excel 进程清理检查。

## 交付物

- Excel 读取接口、COM 实现及数据契约。
- 集成测试样本生成或测试夹具。
- 性能测量记录：至少包含 10 万行样本。

## 完成验证

- `ex_transform.excel_ingestion.ExcelReader` 使用独立 `ExcelApplication`，通过 `Find` 确定值/公式边界，并按可配置行数批量读取 `Value2` 和 `Formula`。
- `CellRecord` 保留文件路径、工作表顺序、物理行列号、计算结果、公式标记和公式文本；格式残留但无值/公式的单元格不会输出。
- `chunk_callback` 支持边读边提交索引，`IngestionProgress` 覆盖文件、工作表和块阶段；`threading.Event` 或取消回调可协作停止。
- 单文件打开/读取异常记录在 `FileReadResult.error` 中并继续处理其他文件；所有成功、失败和取消路径均关闭工作簿并退出私有 Excel 实例。
- `read_async` 在专用后台线程创建 COM apartment；测试覆盖批量读取、公式结果、文件失败隔离、取消和异步入口，当前测试结果为 `9 passed`。
- 真实 Excel 16.0 集成样本验证：`.xlsx`、`.xlsm`、隐藏工作表/行列、公式结果、膨胀 `UsedRange`、损坏文件和源文件哈希/大小/修改时间均通过；10 万行（300000 个单元格）流式读取耗时约 4.0 秒（约 24864 行/秒）。
- 真实独立子进程验证用户已打开同一工作簿时，读取器结束后用户进程和工作簿仍可访问；读取器创建的 Excel 进程在测试结束后清理。
- 真实 `Workbook_Open` 宏对照验证通过：读取器打开时探针单元格保持 `not-run`，允许宏的隔离对照实例打开后变为 `ran`，证明 `AutomationSecurity=3` 阻止了宏执行；两次打开后源文件哈希、大小和修改时间均不变。
