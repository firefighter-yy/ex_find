# TISSUE-001：建立工程基础与环境诊断

- 状态：完成
- 类型：工程
- 优先级：P0
- 依赖：无
- 关联：[ADR-0001](../adr/0001-local-desktop-search-and-excel-automation.md)

## 目标

建立可运行、可测试、可打包的 Python 桌面工程，并在启动时明确诊断 Windows、Python、Microsoft Excel 和 COM 自动化环境。

## 范围

- 建立 `src` 布局、应用入口、测试目录和资源目录。
- 声明并锁定核心依赖：PySide6、pywin32、测试与质量工具。
- 建立应用配置、结构化错误类型和不含敏感数据的日志基础。
- 增加环境诊断：操作系统、Excel 是否安装、Excel 版本、COM 是否可创建。
- 建立统一命令用于启动应用、运行测试和执行静态检查。
- 编写开发环境和运行环境说明。

## 非范围

- 不实现文件读取、搜索、预览或导出业务。
- 不在本任务中制作最终安装包。
- 不自动安装或修改用户的 Microsoft Excel。

## 实现约束

- 应用启动入口不得在模块导入时创建 COM 对象。
- 日志不得记录单元格内容、搜索关键词或完整结果。
- 环境不满足时应显示可理解的诊断信息，而不是 Python 堆栈。
- Excel 诊断创建的自动化实例必须立即可靠退出，不复用用户已有实例。

## 验收标准

1. 开发环境可通过单一命令启动一个空的 PySide6 主窗口。
2. 单元测试和静态检查可通过统一命令运行。
3. 安装 Excel 的目标 Windows 电脑上，诊断可显示 Excel 可用及版本信息。
4. Excel 不可用时，应用给出明确提示且不崩溃。
5. 诊断结束后，任务管理器中不残留由诊断创建的 Excel 进程。
6. 项目文档说明支持的 Python、Windows 和 Office 版本。

## 测试要求

- 应用入口烟雾测试。
- Excel 可用与不可用两条诊断路径测试。
- 日志脱敏测试。
- COM 诊断资源释放集成测试。

## 交付物

- 工程骨架和依赖声明。
- 环境诊断模块。
- 开发与测试说明。

## 完成验证

- Conda 环境：`Ex_Find`，Python `3.12.13`，安装于 `F:\Miniconda3\envs\Ex_Find`。
- 统一测试命令：`python -m ex_transform test`，结果为 `6 passed`。
- 静态检查命令：`python -m ex_transform check`，源码编译通过。
- Excel COM 诊断：Windows，COM 可用，Excel `16.0` 可创建并正常退出。
- Excel 不可用时，诊断输出明确提示且不会抛出 Python 堆栈。
- 日志脱敏测试和 COM 生命周期冒烟测试通过。
